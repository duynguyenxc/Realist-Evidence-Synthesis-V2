# What the open scholarly infrastructure actually does when you automate against it

Generated by `scripts/source_audit.py`. No model was called; this cost nothing.

## The short version

The assignment asks for a broader literature search, so four catalogues this pipeline has no adapter for were added through UWSS and pointed at the same review vocabulary. **Three of the four could not contribute, and only one of them said so.**

That is the result worth reporting, and it is not a complaint about tooling. An automated review does not fail by crashing — it completes, exits zero, and produces a report indistinguishable from a correct one. Counting this audit and the four defects this project had already caught on its own, **five of the nine failures recorded below were silent.**

## The four catalogues, measured

All runs used the same database, which already held the **1,863 records** of the registered corpus, so duplicates against the existing pool are detected rather than counted twice.

| Catalogue | Outcome | Silent? | What happened |
|---|---|---|---|
| **Semantic Scholar** | works, slowly | no | Returns records without a key, but rate-limits hard enough that a full pass over 27 phrases is an overnight job. Usable; not free of friction. |
| **PubMed (NCBI E-utilities)** | blocked | **yes** | Answers HTTP **200** with `Content-Type: text/html` and an "NCBI - WWW Error Blocked Diagnostic" page. `paperscraper` parses it as JSON, fails, and reports **0 records**. Adding the documented `tool` parameter changes nothing. A review would record "PubMed: 0 results" and never learn it was blocked. |
| **arXiv** | works | no | Returned 200 records on the first pass — but the protocol excludes preprints, and the content is the wrong literature anyway: sentiment analysis, emotion recognition, multimodal LLMs, HCI. A measured answer to "should we add arXiv": no, and here is the number. |
| **DOAJ** | broken | no | `discover-doaj` raises `ModuleNotFoundError: No module named 'src.uwss.discovery'` — the module the command imports is not in the repository. A loud failure, which is the good kind. |
| **OpenAIRE** | not attempted | — | Left for a later pass; the four above already answered the question. |

Records each adapter actually inserted: **paperscraper_arxiv** 200, **semantic_scholar** 20.

### The PubMed case, in full, because it is the instructive one

```
GET https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=emotion+regulation&retmode=json

HTTP 200
Content-Type: text/html
<title>NCBI - WWW Error Blocked Diagnostic</title>
```

The status line says success. The content type is the only thing that says otherwise, and no layer between the HTTP client and the review's flow diagram looks at it. The client parses JSON, fails, catches the exception, and reports an empty result set — which is a sentence a reviewer reads as evidence about the literature rather than as a broken request.

## The four this project had already caught, for the same reason

| Defect | Where | Why it was invisible |
|---|---|---|
| OpenAlex ceased to be free and keyless | 2026-02-13; $0.001 a search against a $0.10/day budget shared per network IP | Requests still succeed. Only the bill changes, and the manuscript's credential-free reproducibility claim stops being true. |
| Crossref silently dropped relevance ranking | under `cursor` paging without an explicit `sort` | HTTP 200, a full page of results, and an arbitrary index-ordered slice. Before the fix: 501 records from 1999-2002 with zero abstracts. After: 529 with a median year of 2023 and 40% abstracts. Nothing in the response says the ranking is gone. |
| `--types article` would have discarded the reviews | OpenAlex types `review` separately from `article` | Would have silently dropped Durlak et al. 2011 — 11,017 citations, named by DOI in the assignment itself — and the search would have looked entirely normal. |
| 694 of 1,266 "open access" links yield no file | publisher CDNs refuse scripted requests; 280 were DOI resolvers, not PDF locations | `res acquire` exits 0 and reports completion. The gap between "has an open-access link" and "we hold the full text" was being reported as if it were zero. |

## Why this belongs in the paper

The manuscript argues that a multi-agent pipeline can perform the analytic operations of a realist review while human judgment stays sovereign. The usual objection is that the human checkpoints are decoration — that if the machine is good enough to extract configurations, the human is signing off on work they cannot meaningfully audit.

This audit is the counter-argument, and it is empirical. **Every failure in both tables above produces a review that looks finished.** None would be caught by reading the output, because the output is well-formed. They were caught by checking an assumption against the live service before trusting a run — which is a human operation, performed at a checkpoint, on a question no amount of model capability answers.

It also qualifies the reproducibility claim concretely rather than vaguely. A reader with this protocol, these queries, no API keys and no institutional access does not reconstruct this corpus: one catalogue now bills, one blocks them outright, and two thirds of the nominally open full texts will not come down.

## What has NOT been done with any of this

Nothing found here has been merged into the corpus. `config-emotion/protocol.yaml` registers OpenAlex and Crossref as the search; adding a catalogue changes what the review claims to have searched, which is a protocol amendment and the supervisor's decision. The records sit in a separate database and a separate file, and the arXiv result argues against adding that one at all.
